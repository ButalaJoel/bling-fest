# Security report — Bling Fest (Render + Express version)

Standing SOP applied. 18 Nov 2026. Tested on a real PostgreSQL with the real server and a real browser:
**full applicant → reviewer → admin → public flow passes, and 29/29 automated attack tests pass** (`server/scripts/security-test.ts`), plus manual checks for lockout, session revocation and the audit log.

## Access
| SOP item | Status | How / tested |
|---|---|---|
| Proper authentication | ✅ | Email + password, server-side. Same error for wrong email or password; a dummy hash is checked when the email doesn't exist so timing doesn't reveal accounts. |
| Hash every password | ✅ | bcrypt, cost 12 (DB constraint rejects anything that isn't a bcrypt hash). 10+ characters; obvious passwords refused. |
| Lock down admin routes | ✅ | Every `/api/admin/*` route requires a valid session; account re-checked on every request. Tested: anonymous → 401, forged tokens (wrong secret, `alg: none`) → 401, signed-out visitor sent to sign-in. |
| Role-based access | ✅ | owner / admin / reviewer. Tested: reviewer can't approve, reject or publish (403). |
| Secure session cookies | ✅ **(was ⚠️ in the Supabase version)** | JWT in an **httpOnly, Secure, SameSite=Strict `__Host-` cookie**, 8 h. Page JavaScript can't read it. Website and API share one origin, so no cross-site cookie settings are needed. |
| Session revocation | ✅ | Password change, role change or disabling an account invalidates every existing session immediately (tested). |
| Brute-force protection | ✅ | 10 sign-in attempts / 15 min per connection; account locks 15 min after 5 wrong passwords (tested). Failures go to the audit log. |
| Password reset links expire | n/a now | No emailed reset links exist (no email service yet). The owner resets passwords from the Render Shell (`npm run admin -- password`). If email reset is added later: single-use tokens, stored hashed, 30-minute expiry. |

## Secrets
| SOP item | Status | How |
|---|---|---|
| Keys out of the code | ✅ | All secrets are server-side environment variables. The website has **no** keys at all. `server/.env` git-ignored. |
| Review env variables | ✅ | `DATABASE_URL`, `JWT_SECRET` (generated by Render), 3 Cloudinary values. Server refuses to start in production with a short secret, no Cloudinary, or a leftover `ADMIN_PASSWORD`. |
| Scan for leaked secrets | ✅ | Repo history (2 commits) and build output scanned: no keys. The old Supabase setup was never connected, so no Supabase keys ever existed. |
| Revoke exposed keys | n/a | Nothing exposed. |

## Data
| SOP item | Status | How |
|---|---|---|
| Secure the database | ✅ | Render Postgres with **no internet access** (`ipAllowList: []`). Only the web service connects. CHECK constraints on every column as a second line of defence. |
| Parameterised queries | ✅ | Every query uses `$1, $2…` placeholders. Tested: `' or 1=1; drop table…` in search returns 0 rows; `%` is matched literally. |
| Validate every form on the server | ✅ | Every field re-checked on the server (types, lengths, allowed values, email/phone/URL). Tested: status sent by an applicant is ignored (always `pending`); `javascript:` links, unknown categories, missing consent and over-long text rejected. |
| Restrict upload types and sizes | ✅ | JPG/PNG/WebP only, **real type checked from the file's bytes**, 5 MB each, max 6. Tested: fake JPEG with code inside, SVG, 5 MB+ file and 7 files all rejected. Photos are private Cloudinary assets; admins see them via links that expire after 5 minutes. |
| Verify prices/payments on the server | n/a | No payments in v1. |

## Web
| SOP item | Status | How |
|---|---|---|
| HTTPS | ✅ | Render provides HTTPS; HSTS (2 years, preload) + `upgrade-insecure-requests`. |
| XSS | ✅ | React escapes output; no raw HTML rendering; links pass an http(s)-only check and open with `noopener noreferrer`. CSP `script-src 'self'`. Control characters stripped from input. |
| CSRF | ✅ | SameSite=Strict cookie **plus** a required custom header **plus** Origin check on every change. Tested: missing header → 403, foreign Origin → 403, even when signed in. |
| Restrict CORS | ✅ | CORS is not enabled at all: same origin only. |
| Security headers | ✅ | CSP, HSTS, X-Frame-Options DENY, frame-ancestors none, nosniff, Referrer-Policy, Permissions-Policy, CORP/COOP; `X-Powered-By` removed (tested). |
| Rate limiting | ✅ | Applications: 10/hour per connection, 3/day per email, 40/10 min site-wide. Sign-in, admin writes and public reads limited too (tested). |

## Remaining recommendations
- Add a CAPTCHA (Cloudflare Turnstile, free) to the application form before heavy promotion.
- Rate limits are kept in memory: fine for one Render instance; move them to the database or Redis if you scale to several.
- Cloudinary "authenticated" photos: download links expire after 5 minutes, but anyone with the Cloudinary account login can see them — protect that account with 2FA.
